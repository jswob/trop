## The rows

**Rows 1 and 2, the load** (G2). M0's engine evaluates nothing, and its tests must stay green once M1 evaluates, so a text set's load is seen through the **load probe**, `run <files> --ask zz_m0_probe`: an ask no text declares. Load runs first and a load refusal prints as in any run; after a clean load the run prints `refused: REQ-ASK no ask zz_m0_probe` alone and exits 1, whatever the reality's shape (one model, scenarios, a joint model; E §11, tally 2.1.3, #58; `INTERFACE.md` § The load probe). `m0/vectors.py` runs the probe on refcore 2.1.3 for each of the 315 text sets (the same sets, tables and groups as row 4) and stores refcore's whole run in `m0/load.refcore` (seven netstrings: id, group, cwd, the command line, the file table, the exit code, the output). Before it writes, it ties each probe to every stored output of `checks.tsv` that runs its set, so no expected value is new: a stored output whose first line is `refused: …` (a load refusal) must be the probe's whole output, and any other must give the REQ-ASK line. 304 sets load clean; 11 are refused: `I:M:MP-10` (`LOAD-BAND`) and row 1's 10.

A scenario's own load refusal refuses that scenario alone (`scenario <s>: refused: …`), and the probe can't show it: the base loads clean. For each scenario a stored output shows refused, the set gets a second vector, `<set>#<scenario>`, that asks the asks the scenario's file declares (refused with it; no evaluation needed), and the tie wants each stored `scenario <s>: refused: …` line in its output: `I:B:b10_v3#hr2_v3` (`LOAD-CYCLE`) and `U:set/rule/RULE-09/RULE-09#inpath` (`LOAD-ASKONLY`). `U:set/surf/SURF-04/SURF-04`'s `redefine` declares no ask, so only a full run shows its refusal (M1's); `vectors.py` lists it and writes no vector. Row 1's 10 checks are vectors of their own, `refusal/<id>`: the check's command line as `checks.tsv` writes it, its stored baseline as the expected output (refcore's run of it prints the baseline, byte for byte, or `vectors.py` stops).

`m0_load` runs each vector in process and wants refcore's exit code and whole output, with `warning:` lines left out on both sides: a run that isn't refused whole prints load's warnings after its answers, and the warnings are M1's (BUILD-ORDER § M1, L §8.5), though load decides `WARN-UNREAD` (E §3.1 step 6). Only `I:B:b10_v3#hr2_v3` prints any (18 `WARN-UNREAD` lines). One test per corpus group (the 12 of row 4; the two `#` vectors in theirs) and one per row 1 check: 22 tests, 327 vectors.

**Row 3, the scan and the loader** (G5). `m0/loadcheck.py` loads the spec's scan, `engine/spec/tools/loadcheck.py`, read-only, runs its `--selftest` first (31 planted refusals, all found, no look-alike), then the scan and refcore 2.1.3's load probe over **90 realities**: the 79 models of `engine/spec/models/`, each a file (LH-15 and LH-16 at full size; the other 77 are byte for byte `integration/models/`), the household `engine/spec/amendments/household/` (13 files) and X's changes `c1`..`c7` and variants `v3`..`v5` (`integration/amendments/real11/`, each a folder). They agree when the scan refuses and refcore refuses with one of its codes at one of its places, or the scan is clean and refcore loads clean or refuses with a code the scan doesn't check. Today the scan is clean on all 90, and refcore on 89: MP-10's `LOAD-BAND` is outside the scan.
