# Goldens and pins on the v2 concepts

The spec (§8.1, §8.2) says the new engine reproduces G1–G10 and the 36 pins, or explains each difference by a finding it fixed. This file maps each one onto the v2 constructs it uses and says whether the v2 semantics (as adopted in spec §15) could change its value.

- **Unchanged:** the v2 construct gives the same number on the prototype's fixture, for the reason given.
- **Changes form:** same number, but the engine reaches it, or refuses, through a different construct (a new required statement, a refusal instead of a warning).
- **May move:** the v2 or spec semantics can give a different number on the same fixture. Each one names what decides it.

Checked on paper against the fixture files in `tmp/blocks/cases/` and `tmp/blocks/pins-1-7.json`. Nothing here was run.

## Findings for `changes.md`

- **The digests can't survive v2 as hashes of the whole output.** Pin a canonical projection instead.
- **Ownership is now needed to compute net worth and per-party limits,** and the fixture states none. Either a default ("all places are the household's, jointly") is written into the fixture as a stated fact, or G1, G3 and every net-worth pin become holes.
- **The joint-return pins conflict with L-26** if art. 6 ust. 8 bars this household (ryczałt). That is a law fix the spec already lists, so the pins may move under §8.2's rule ("a pin may move only where a listed finding is fixed"); L-26 should be added to that list next to F8.
- **G6 needs one more statement** (how the raise meets the wage index, L-03), or it can't run under the spec.
