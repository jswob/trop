Model: `models/MP-10.tally`. Case: `tmp/verification/cases/MP-10.md`.

## The expected response: the model is refused at load

Case locator: "## Published answer", last paragraph: "Expected response under tier `refusal`: the copy is invalid as a lookup table, because the bands of groups 10/11, 11/12, 12/13, 13/14 and 14/15 overlap."

The model transcribes the band rows as printed (case "## Inputs", table, column "Nettoeinkommen des Unterhaltspflichtigen", rows 1–15) into one table, version `hanau2026`. The band's argument is an `int`, so rows 1–10 meet without a gap over the integers (2100 / 2101 and so on). Row 11, `[5501, 6400]`, overlaps row 10, `[5301, 5700]`. The loader refuses:

`LOAD-BAND: band hanau_group in hanau2026: rows unordered, overlapping or with a gap at 5501`

The first overlap is at 5501, between groups 10 and 11. The case's own check gives the other four: `python3 -c "print(5700 >= 5501, 6400 >= 6201, 7200 >= 7001, 8200 >= 8001, 9700 >= 9501)"` → `True True True True True` (case "## Transcription notes", arithmetic checks).

A load refusal stops the model before anything runs (LANGUAGE.md §8, ENGINE.md §11). **Every ask therefore prints the refusal, not a value.** That includes the asks that don't read the band: LANGUAGE §5.8 says so ("nothing prints from an inconsistent law table, asks that never read the band included").

The version's known date, 2026-01-02, is the copy's earliest public stamp, the server's Last-Modified, since it prints no date of its own (LANGUAGE §4.5; D8: earlier rounds took the PDF's own modified stamp, the same day). It doesn't change the refusal.

## If the table were fixed

Not the expected response; for an evaluator checking the rest of the model. If the band rows of groups 11–15 were replaced by the official edition's lower bounds (case "## Inputs", second table, column "Official 2026 (source 1)": 5.701, 6.401, 7.201, 8.201, 9.701), the model would load. `q_zahlbetrag` would then reproduce each Hanau Zahlbetrag of the Published answer table. The case checks three of them:
- `python3 -c "from decimal import Decimal as D; print(D('486')-D('129.5'), D('558')-D('129.5'), D('653')-D('129.5'))"` → `356.5 428.5 523.5`
- `python3 -c "from decimal import Decimal as D; print(D('1150')-D('129.5'))"` → `1020.5`

Money prints as 356.50 and so on. The `a18` column has no Zahlbetrag in the copy, so the model gives a hole there (rule `zahlbetrag.adult`); `q_zahlbetrag` binds only the three minor age bands.
