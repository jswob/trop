# Tally engine: done when

The acceptance contract for the Rust engine (step B), written before the build. The engine is done when every gate below is green on one tagged commit, as run by a gate session, never by the builder. It is the user's contract: a gate changes only with the user's approval, logged here with its date.

**Status:** approved by the user, 2026-10-19, for tally 1.0 and 1.0.1. Restated for tally 2.0 at gate G2, 2026-10-27: the proposals of the design round (`tmp/design2/DONE-proposals.md`), with the user's G2 decisions folded in. Restated for tally 2.1 at session 7b's G2, 2026-10-30: rule 1 names `tally 2.1` (logged in the table).

## The rules the gates rest on

1. **The spec is frozen as `tally 2.1`** in `engine/spec/` of this repository, the commit tagged `tally-2.1`: `LANGUAGE.md`, `ENGINE.md`, `DECISIONS.md`, `CHANGES.md`, `MIGRATION.md`, `coverage.md`, `VERSION`, `SHA256SUMS`, and the models, expected files, amendments, `montecarlo/` and `tools/loadcheck.py` they cite. The reference interpreter is frozen beside it, in `engine/tools/refcore/`. `tally-1.0`, `tally-1.0.1` and `tally-2.0` stay reachable by their tags.
   - `OPERATIONS.md`, `PERFORMANCE.md`, `BOUNDS.md` and `BUILD-ORDER.md` are frozen as **stale**, with the sections tally 2's decisions reach (`STALE.md`). A gate that cites them (5, 12 and the milestones) waits until each is rewritten for tally 2.
   - After the freeze, a change to the spec needs three things: a failing test or a logged contradiction, a row in `CHANGES.md`, and a patch that names both. Each patch raises the version (`tally 2.1.1`, …), and every gate is re-run on it.
2. **The tests are not the builder's.** Step T writes them from the frozen spec and the answer keys. A guard refuses every edit to tests, vectors and expected values from the build session. When a test looks wrong, the builder stops and reports it; one hand run decides whether the model, the spec, the test or the code is wrong, and the decision is logged.
3. **No silent fix.** Where the spec is unclear, the spec is fixed first (rule 1), never only the code.
4. **Every gate is evidence, not a claim.** Each gate's evidence is a CI run on the tagged commit, whose log is kept.

## What "done" doesn't promise

- **Laws unlike any tested case.** The final 5 measure this; nothing proves it.
- **Tally 2's breadth beyond the visible cases.** The design round saw the 79 models, the visible cases and its blind cards, never the holdout; session 5's scoring measures it.
- **The bounds of tally 2.0 the user accepted at G2.** A redemption across two versions of an act (`Q:D-07`, figures 6 and 7) can't be written; a refusal outranks a hole, so a refused line never lists the other missing facts (`Q:A-10`); the rows that stay awkward are listed with the user's ok in `CHANGES.md`. Namespaces and modules (the dropped `regime`) are tally 3.0's.
- **Modelling the household's real data well.** That is the product check, outside the engine and its tests.
