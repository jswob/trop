# The engine's scaffold

What the scaffold sets up around the engine, before a line of it is written: the Cargo workspace and its stubs, the lints and bans, the guard, the checks, and CI. It was built in phase 1 from the brief `tmp/active/engine-scaffold.md` (C, revised at gate 2 on 2026-10-22) and the rulebook the user approved at gate 1 (`tmp/research_notes/engine-rust-strictness/RULEBOOK.md`). `SCAFFOLD-REPORT.md` holds the checks and their output.

Every crate is a stub: `parse` and every CLI command answer "not implemented". Nothing here reads Tally's syntax. The scaffold encodes principles and gates: exact numbers, determinism, no crash, the DONE gates, the guard.

## 1. Layout

  deny.toml                   cargo-deny over the whole workspace: allow-lists, bans, licences,

## 3. Sessions and roles

The guard is a Claude Code PreToolUse hook (`engine/tools/guard`), set in `.claude/settings.json`. It reads the role from `TALLY_ROLE` when the session starts. Every session starts at the repo root.

| Session       | Started with              | Who                                            | May write                                                                                                                                                                                                                                          |
| ------------- | ------------------------- | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The build     | `TALLY_ROLE=build claude` | the builder                                    | its allow-list only: `engine/crates/**` (no `build.rs`, no `benches/`, no config file, no `.cargo/`), `engine/Cargo.toml`, `engine/Cargo.lock`, `engine/BUILD-LOG.md`, `engine/MUTANTS-SURVIVORS.md`, `engine/EXCEPTIONS.lock`, `engine/target/**` |
| T, the tests  | `TALLY_ROLE=tests claude` | the test owner                                 | `engine/tests/` only, including `engine/tests/TESTS.sha256`                                                                                                                                                                                        |
| A rule change | `TALLY_ROLE=rules claude` | the clean-side lead, through R-112 (section 6) | everything but `engine/spec/`, the oracle and `engine/tests/`                                                                                                                                                                                      |
| A spec patch  | `TALLY_ROLE=spec claude`  | the clean-side lead only                       | `engine/spec/` and the oracle only, through the patch rule in `engine/README.md`                                                                                                                                                                   |
| App work      | `claude` (role unset)     | anyone                                         | anything but the spec, the oracle, the tests and the rule files                                                                                                                                                                                    |

**The rule files** are refused to every role but `rules`: `clippy.toml`, `deny*.toml`, `sgconfig.yml`, `rust-toolchain*`, `.cargo/*`, `.config/*`, `tools/*` (with the ast-grep rules), `fuzz/*`, `crates/*/benches/*`, `.github/workflows/engine.yml`, `.claude/settings.json`, and any `clippy.toml`, `rustfmt.toml`, `rust-toolchain*` or `.cargo/` anywhere under `engine/`. Their checksums are in `tools/RULES.sha256`. A role the guard doesn't know refuses everything.

**The oracle** is the spec's reference interpreter: `tools/refcore/`, `tools/refcore_fast/` and `tools/SHA256SUMS` (refcore's checksums). It lives in `tools/` but isn't a rule file: like the spec, only the `spec` role writes it, and `check-frozen` holds it to `tools/SHA256SUMS` and to the commit `tools/frozen.toml` pins. Every role may run it.

**What the guard checks.** `Edit`, `Write`, `MultiEdit` and `NotebookEdit` by their path. `Bash` by a tripwire: it refuses a command that names a protected path together with a form that writes: a writing command (`cp`, `mv`, `rm`, `sed -i`, `tee`, `truncate`, …), a redirect, an interpreter given a path or code that names one, a git command that writes the tree (`checkout`, `restore`, `reset`, `stash`, …), or `find` with `-delete` or `-exec`. In the build role it also watches `~/.claude` and `~/.cargo`, refuses `disableAllHooks`, a nested `claude` run (R-81), a command naming `TALLY_ROLE` (R-79) and whole-tree git operations. In every role but app work it refuses a commit message with an AI co-author or attribution line (R-100).

**The other two hooks.** ConfigChange, in the build role, refuses a settings change and logs `CONFIG-CHANGE BLOCKED` in `BUILD-LOG.md` (R-81). Stop, in the build role, runs `tools/check fast` and keeps the turn going while it is red, unless a STOP-REPORT heading was added to `BUILD-LOG.md` since the last commit, or by it; after three identical blocks it lets the fourth stop through and logs `STOPPED RED` (R-83). `BUILD-LOG.md` holds the STOP-REPORT's template.

**It fails closed.** The shim `tools/guard` turns any exit but 0 into 2, so a crash refuses the call; the hook's command in `settings.json` refuses every call when `engine/` exists and the guard doesn't (R-79). `guard-test` forces an internal failure to prove it.

**Its limits.**

- The Bash check is a tripwire, not a wall. It can't see what a script run by an interpreter writes (`python3 x.py`, where `x.py` writes a rule file). The wall is the checksums: `check-frozen` fails on any changed byte of the spec, the oracle, T's tests or a rule file, and CI runs it on a clean runner.
- It guards Claude Code sessions only. A person's own shell isn't guarded, and neither is a session started with a different `TALLY_ROLE`: the role is trusted as set at launch.
- A worktree's `.claude/settings.json` isn't loaded by the session that wrote it, so the guard binds the next session started there.
- Each role's reach is by path. The `rules` role can write every rule file, which is why a rule change takes the user's dated approval and its own commit (R-112), and the audit reads every such commit.

## 4. Setting the kernel at S (R-85)

At milestone S the lead takes the kernel's file list from the builder's plan and, in the `rules` role, in one commit:

1. In `tools/kernel.toml`: lists the kernel's globs in `kernel` (the numbers and rounding, the read rule, the walk and `plan_low`, booking and the ledger: gate 8), the other library files in `protected_non_kernel`, and sets `set_at_s = true`.
2. In `.cargo/mutants.toml`: sets `examine_globs` equal to `kernel`.
3. In `tools/exceptions-budget.toml`: names the lexer and parser files under `lexer-parser`, and the thread module under `thread`, when it exists.
4. Runs `tools/check-frozen --write-rules`, then `tools/check full`.

From then on check-rules fails on a library file in neither list and on `examine_globs` differing from `kernel`; `mutants-survivors` fails instead of reporting; the advisory lists kernel functions without a spec citation.

## 6. Changing a rule: R-112's procedure

1. **The builder stops.** A STOP-REPORT in `BUILD-LOG.md` names the rule, the blocked code, the command with its exit code, and the strict alternative it tried.
2. **The lead reproduces it** in a clean checkout and decides whether the code, the test, the rule or the spec is wrong.
3. **The user approves the change in plain words.** The approval goes into the rulebook, dated.
4. **One commit by the `rules` role** holds: the config change; its selftest case in `tools/rules-selftest/cases/` (a new rule gets a planted violation; a loosened one gets a case showing what still fires); the map row in this file (section 7); `tools/frozen-lints.toml` if a lint or profile table changed (`check-rules --write-frozen`); and `tools/RULES.sha256` (`check-frozen --write-rules`), written last.
5. **`tools/check full` passes** before the commit, rules-selftest included.

A toolchain bump (R-61) and a budget raise (R-111) go the same way. A spec patch is not a rule change: it follows `engine/README.md` in the `spec` role.

## 7. Every rule, its enforcement and its proof

One line per rule: the rule (shortened; the rulebook has its full text), what enforces it, and what proves the enforcement fires. "selftest" names the cases in `tools/rules-selftest/cases/R-<n>.case`; each plants a violation and must fail with the rule's own name (a lint code, an ast-grep rule id, a cargo-deny code or the script's message). "The ban coverage" is the selftest's planted use of every one of clippy.toml's 481 ban entries, each of which must fire. "Review only" rules have no tool. Running `tools/rules-selftest/run --list` prints the same mapping from the case files.

- **R-1** No `unsafe` code anywhere. **Enforced by:** rustc, error with no exception (`unsafe_code`), plus `#![forbid(unsafe_code)]` at each crate root. **Proven by:** selftest: `unsafe-block`, `crate-root-without-forbid`.
- **R-2** No `unwrap` or `expect` outside tests. Tests may use them. **Enforced by:** clippy, error with no exception (`unwrap_used`, `expect_used`); tests exempted in clippy.toml; ast-grep (`no-unwrap-path`, error) for the forms written as paths (`map(Option::unwrap)`, `Result::expect(r, …)`), tests exempt. **Proven by:** selftest: `unwrap`, `expect`, `tests-may-unwrap`, `unwrap-method-ref`, `result-expect-path`, `tests-may-unwrap-path`.
- **R-3** No crash macros: `panic!`, `todo!`, `unimplemented!`, and `unreachable!` as an error with a counted exception. **Enforced by:** clippy (`panic`, `todo`, `unimplemented` no exception; `unreachable` error). **Proven by:** selftest: `panic`, `todo`, `unimplemented`, `unreachable`, `tests-may-panic`.
- **R-4** No `assert!` family outside tests. An invariant is a real check that returns a refusal. **Enforced by:** clippy.toml (`disallowed-macros`), two clippy passes; `panic_in_result_fn` as a backup. **Proven by:** selftest: `assert`, `assert-eq`, `debug-assert`, `assert-in-result-fn`, `tests-may-assert`.
- **R-5** No `x[i]` indexing or `x[a..b]` slicing on lists, arrays or maps; use `.get` and handle the miss. **Enforced by:** clippy, error (`indexing_slicing`); tests exempted; ast-grep (`no-index`, error) on every index expression outside tests, maps included, which `indexing_slicing` skips. clippy.toml bans `Index::index` and `IndexMut::index_mut` called by path (audit F-12). **Proven by:** selftest: `index`, `slice`, `tests-may-index`, `map-index`, `index-ast-grep`, `tests-may-index-ast-grep`.
- **R-6** No byte-range slicing of text, `s[a..b]`. **Enforced by:** clippy, error (`string_slice`). **Proven by:** selftest: `string-slice`.
- **R-7** No standard-library call that crashes on bad input when a non-crashing twin exists: `Vec::remove`, `split_at`, `RefCell::borrow_mut`, integer `pow`, `abs`, `ilog`, `div_euclid`, `chunks`, `step_by`, `clamp`, and about 30 more. Sort comparators must be total orders. **Enforced by:** clippy.toml (`disallowed-methods`); review for comparators. **Proven by:** selftest: `vec-remove`, `split-at`, `integer-pow`.
- **R-8** Plain-integer overflow in a release build crashes instead of silently wrapping round. **Enforced by:** Cargo profile (`overflow-checks = true` in release and bench). **Proven by:** selftest: `release-overflow-crashes`, `bench-overflow-crashes`.
- **R-9** A crash stops the process at once: no unwinding and no catching it. **Enforced by:** Cargo profile (`panic = "abort"`); clippy.toml bans `catch_unwind`. **Proven by:** selftest: `release-crash-aborts`, `catch-unwind`.
- **R-10** The program ends only by returning from `main` with an exit code: no `process::exit` or `process::abort` anywhere. **Enforced by:** clippy, error with no exception (`exit`), plus clippy.toml for the `main` case the lint skips. **Proven by:** selftest: `exit-in-library`, `exit-in-main`, `abort`.
- **R-11** No print macros anywhere, the CLI included; the CLI writes its output bytes itself and handles a failed write. **Enforced by:** clippy, error with no exception (`print_stdout`, `print_stderr`, `dbg_macro`). **Proven by:** selftest: `println-in-library`, `eprintln-in-library`, `dbg-in-library`, `println-in-cli`, `println-in-tests`, `dbg-in-tests`.
- **R-12** Command-line arguments are read once, in `main`, in the form that can't crash. **Enforced by:** clippy.toml bans `args` and `args_os`; the exception lives in the CLI's sanctioned file (R-108). **Proven by:** selftest: `args`, `args-os-outside-main`.
- **R-13** No `unwrap`, `expect`, crash macro or assert inside a macro definition. **Enforced by:** ast-grep (`no-panic-in-macro-body`). **Proven by:** selftest: `unwrap-in-macro`, `assert-in-macro`.
- **R-14** A conversion never crashes inside. **Enforced by:** clippy, error (`fallible_impl_from`). **Proven by:** selftest: `fallible-from`.
- **R-15** No loop without a way out. **Enforced by:** clippy, error (`infinite_loop`). **Proven by:** selftest: `infinite-loop`.
- **R-16** Nesting is bounded by a **counted** depth, checked before going one level deeper; the stack is never measured. **Enforced by:** review, fuzzing, deep-input tests; cargo-deny bans `stacker`. **Proven by:** selftest: `stacker`.
- **R-17** A proof that a function can't panic, checked at link time. Dropped at gate 1.
- **R-18** No floating point anywhere: no `f32`/`f64` type, no float arithmetic, no float literal, in macros and in code compiled only on some machines too. There is no Monte Carlo exception: the spec has none. **Enforced by:** clippy, error with no exception (`float_arithmetic`); clippy.toml bans the types; ast-grep (`no-float`) catches literals and suffixes. **Proven by:** selftest: `float-arithmetic`, `float-type`, `float-literal`, `float-suffix`, `float-in-cfgd-off-code`, `float-in-macro`.
- **R-19** Plain-integer `+ - * / %` only through checked operations. No type is exempt, the big-integer types included. **Enforced by:** clippy, error (`arithmetic_side_effects`, its allowed list empty). **Proven by:** selftest: `integer-add`, `integer-mul-assign`, `bigint-add`.
- **R-20** No operator written as a method call. **Enforced by:** clippy.toml (`disallowed-methods` on the `std::ops` methods). **Proven by:** selftest: `add-method`, `shl-assign-path`.
- **R-21** No `as` casts between number types; use conversions that can fail and refuse. **Enforced by:** clippy, error (`as_conversions`). **Proven by:** selftest: `as-cast`.
- **R-22** No integer `/` or `%` operators: written out as `checked_div_euclid`, `checked_rem_euclid` and friends. **Enforced by:** clippy, error (`integer_division`, `modulo_arithmetic`). **Proven by:** selftest: `integer-division`, `modulo`.
- **R-23** No silent clamping or wrapping: no `Wrapping` or `Saturating` types, no `saturating_*`, `wrapping_*` or `overflowing_*` calls. **Enforced by:** clippy.toml bans the types; ast-grep (`no-wrapping-arith`) bans the calls. **Proven by:** selftest: `wrapping-call`, `saturating-call`, `overflowing-call`, `wrapping-type`.
- **R-24** No `Iterator::sum` or `product`; fold with checked additions. **Enforced by:** clippy.toml, the trait methods `Sum::sum` and `Product::product` too (audit F-12). **Proven by:** selftest: `sum`, `product`; the ban coverage.
- **R-25** No call that converts to or from a float: `to_f64`, `from_f64`, `Duration::as_secs_f64` and their siblings. **Enforced by:** clippy.toml. **Proven by:** the ban coverage.
- **R-26** No big-integer call that skips the size check: `BigInt::pow`, `Pow::pow`. **Enforced by:** clippy.toml. **Proven by:** the ban coverage.
- **R-27** No silent default: `unwrap_or_default` is banned, and the two clippy lints that recommend it are switched off. `unwrap_or`-style defaults are listed for review. **Enforced by:** clippy.toml ban (error); ast-grep `silent-default-*` (report). **Proven by:** selftest: `unwrap-or-default`, `result-unwrap-or-default`, `literal-default`, `default-call`.
- **R-28** `Num` and `Money` get no operators, no "zero value", no `Sum`, no conversion from a plain integer or a float. Money comes back from a calculation only through a `round`. **Enforced by:** review, plus the builder's compile-time assertions; the type names are the builder's (C §2 rule 6). **Proven by:** review only.
- **R-29** Only the number kernel names the big-integer types; its exceptions to R-19 sit on single functions in kernel files the lead lists. **Enforced by:** clippy.toml bans the types; cargo-deny lets only `tally` depend on num-bigint; R-108 keeps the exceptions in their files. **Proven by:** selftest: `num-bigint-outside-tally`, `bigint-type`.
- **R-30** One number stack, exactly pinned, with default features off: num-bigint 0.4.8, num-integer 0.1.47, num-traits 0.2.19. Every alternative is banned by name, as are the features that bring floats or randomness. **Enforced by:** `[workspace.dependencies]` and cargo-deny (bans and feature bans). **Proven by:** selftest: `pin-loosened`, `default-features-on`, `num-traits-std`, `num-rational`, `second-big-integer`.
- **R-31** Rounding lives in one module, the seven modes of LANGUAGE §7.2 written once. **Enforced by:** review (the module name is the builder's). **Proven by:** review only.
- **R-32** Fields named like money typed as plain integers listed for review. Dropped at gate 1.
- **R-33** Number literals must say their type. Dropped at gate 1.
- **R-34** The float-precision lints. Dropped at gate 1.
- **R-35** A custom compiler plugin for "no expression of float type" and "the number crate only inside the money module". Dropped at gate 1.
- **R-36** No hash maps or hash sets, no randomly seeded hasher, and no std `DefaultHasher`. Use sorted maps, or an insertion-ordered map with a reason. **Enforced by:** clippy.toml bans the types; clippy, error (`iter_over_hash_type`) as a backup for maps a dependency returns. **Proven by:** selftest: `hashmap-type`, `iterate-a-hash-map`, `default-hasher`.
- **R-37** No hash-map look-alike crates in the shipped library. **Enforced by:** cargo-deny on `tally`'s own graph. **Proven by:** selftest: `hashbrown`, `ahash`.
- **R-38** No clock: no `SystemTime`, `Instant`, `sleep`, and no date crate's "now" or clock features. **Enforced by:** clippy.toml; cargo-deny feature bans (chrono's `clock` and `now` both). **Proven by:** selftest: `chrono-clock`, `system-time`, `instant`.
- **R-39** The library touches no environment variables, files, stdin or stdout, processes or network. It takes the reality as bytes. ## 8. Deviations from C

Where the scaffold differs from `tmp/active/engine-scaffold.md`, and why.

**Results C expected that came out otherwise**

1. **The counter prints 5, not 0.** The stubs need five exceptions. Three are in the CLI's sanctioned file: reading the arguments (`args_os`), reading standard input and writing the output. C prescribes all three for `main.rs`, and clippy.toml bans each call everywhere else. The other two are in `deny.toml`: a skip for `syn` 2, which `zerocopy-derive` (criterion, dev only) still uses beside `syn` 3, and a build bypass for `zerocopy`, which ships its maintainers' CI shell scripts. All five carry `R-<n>:` reasons and are in `EXCEPTIONS.lock`. The CLI's budget is 3, so it is now full (section 9, open questions).
2. **`bun lint` failed in a checkout where the engine had been built**, so two files outside C's write list gained ignore lines, with the user's go (2026-10-23). ESLint linted the JavaScript that rustdoc writes under `engine/target/`, because the root `eslint.config.js` didn't ignore it; `'engine/'` is now in its `ignores`. Prettier had the same blind spot: it reads only the root ignore files, so `bun format` would have reformatted the engine's build output. `.prettierignore` now lists `engine/target/`, `engine/fuzz/target/`, `engine/mutants.out/` and `engine/mutants.out.old/`.

**Commands C gave that the tools reject**

3. **cargo-deny's `--config` is a top-level flag.** C's command put it after `check`, which cargo-deny 0.20.2 rejects. The command is `cargo deny --manifest-path crates/tally/Cargo.toml --config deny-tally.toml check bans`.
4. **cargo-mutants 27.1.0 ignores `test_package` in its baseline.** It tests the mutated package (`tally`, which has no tests), so the baseline fails. Every run therefore runs the baseline itself on T's runner (`cargo nextest run -p tally-runner --cargo-profile mutants --profile mutants`), then calls cargo-mutants with `--baseline skip`. Without a baseline, cargo-mutants can't derive timeouts, so every command line passes `--timeout 300 --build-timeout 600` (R-88). The mutant runs were checked to use `--package=tally-runner`.

**Additions: tool gaps the selftest exposed, each closed by a check of its own**

5. **R-45:** clippy's `use_debug` sees only the `print!` and `write!` families, not `format!`. The ast-grep rule `no-debug-format` catches `{:?}` in any macro's string, with test modules, `tests/` and `benches/` exempt.
6. **R-59:** cargo-deny's `workspace-duplicate` fires only when two members declare a crate. check-rules therefore requires every dependency of an `engine/crates/*` member to be `workspace = true`. It doesn't apply to `tests/runner`, because T can't edit the root `Cargo.toml`.
7. **R-71:** clippy's `missing_assert_message` skips test code, and tests are the one place asserts are allowed. check-rules scans `crates/` and `tests/` for `assert!`, `assert_eq!` and their siblings without a message.
8. **R-1:** check-rules also requires `#![forbid(unsafe_code)]` at each crate root. Without it the rule rests on the workspace lint alone.
9. **R-29:** "only `tally` depends on num-bigint" lives in check-rules (from `cargo metadata`) and in clippy's type ban. cargo-deny can't hold a crate both on the allow-list and in `deny` with wrappers.
10. **The root `engine:*` scripts are frozen.** `package.json` can't be a rule file, since app work edits it, so check-rules compares each `engine:*` script with its copy in `tools/frozen-lints.toml`.

**Choices C left open**

11. **The CLI's exit codes are 64 (usage), 69 (not implemented) and 74 (an I/O failure).** These are placeholders, clear of 101 (a panic) and 134 (an abort). T's interface replaces them. When standard input is a terminal, the stub reads it as empty instead of waiting.
12. **The runner package is `tally-runner`.**
13. **A `release-test` profile:** release settings with debug assertions on. The fault-injection feature refuses to compile without debug assertions (R-51), and gate 5 needs it under the release-profile tests.
14. **`main.rs` is split into three small functions,** each holding one exception, so `main` holds none. That way a `process::exit` written in `main` still fails (R-10).
15. **The CLI's binary has `doc = false`.** It and the library are both named `tally`, so their doc pages collided ("output filename collision").
16. **The advisory thresholds** are clippy's defaults, 100 lines and cognitive complexity 25, report-only (R-74 amended; phase 1's were 60, 20 and nesting 4). Nesting is an error at 5 in the strict passes since session 8c.
17. **special-casing reads the suite T inherits** (re-pointed at session 8c, merge M-9, the user's "yes" 2026-10-31): the check and case ids from `checks.tsv` and the case files, the `ask` lines of the inputs `checks.tsv` names, and the values of 4+ significant digits in `baselines/`, skipping every path that holds `hidden` or `holdout`. It fails when the suite exists and gives it nothing to search for; otherwise it reports and exits 0. It runs in `check full`.
18. **The `lexer-parser` and `thread` areas have empty globs until S.** Until then their code counts as the library, whose budget is also 0.
19. **The chrono feature ban is anticipatory.** chrono isn't a dependency, and the selftest proves the ban on a fake crate.

**Changes to how the tools are laid out and run**

20. **`check fast` also runs check-frozen and check-rules.** They are cheap, and they catch the build's own `Cargo.toml` edits on every turn.
21. **`check` clears more than C's list.** On top of C's, it also clears `RUSTDOCFLAGS`, `CARGO_ENCODED_RUSTDOCFLAGS`, `RUSTC`, `RUSTDOC`, `CLIPPY_ARGS`, `RUSTUP_TOOLCHAIN`, `CARGO_INCREMENTAL`, `CARGO_UNSTABLE_*`, `NEXTEST_*`, and `CARGO_TARGET_<triple>_*` (`CARGO_TARGET_DIR` stays). It also gained `check step <name>`, which the selftest's R-82 cases use.
22. **rules-selftest is a directory:** `tools/rules-selftest/run`, plus `cases/R-<n>.case`, one file per enforced rule. A case that misses inside a batch is rerun alone before it counts. A compile error in a batch is reported, because it stops every lint in that batch.
23. **`ast-grep test` runs with `--skip-snapshot-tests`.** No snapshot files are kept. The rules' tests check their valid and invalid snippets, and the selftest checks the rule ids.
24. **The ast-grep YAML is in Prettier's style,** so `bun format` leaves the checksummed rule files alone. The parsed YAML was checked to be identical before and after.
25. **`mutants-survivors` reports and exits 0 until S,** because the stubs' one mutant is caught by nothing. From S it fails under 90 % (gate 8) and on any unlisted survivor.
26. **CI:** the workflow runs on pull requests into `master` and into `engine`, the long-lived branch the engine's work merges into (the user's go, 2026-10-23). It uses a YAML anchor for the install step, which actionlint accepts. It fetches tags, because check-frozen compares the spec with its tag. Its nightly jobs write reports, and only mutants and the benchmarks can fail.
27. **`engine/.gitignore`** also ignores `mutants.out/`.

**Changes at session 8c (2026-10-31)**

28. **`.claude/settings.json` enables the `rust-analyzer-lsp` plugin** (`enabledPlugins`). The user installed it on 2026-10-30, as G1's D6-5 approved. The install rewrote the file in two-space indents, which turned check-frozen red; the commit keeps the plugin, restores the repo's tabs and rewrites `tools/RULES.sha256`. The `spec-loadcheck` step and `bun engine:spec-check` pass it the 79 models and the household, BUILD-ORDER's list; the changes are Markdown, which tally 2's scan doesn't read.
