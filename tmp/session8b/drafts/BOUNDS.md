# Tally: honest bounds

The 49 rows of `tmp/verification/bounds.md`, with the design's answer to each, plus four rows (50–53) for abilities the design added and one (54) for tally 2.1's labels. Rewritten for **tally 2.1** (session 8b): each row's *Tally* column and note name 2.1's constructs and sections. Nothing here was built or run.

**No status moves because of the design or of this rewrite.** A gap stays a gap until the ability is built (the user's decision, 2026-10-18), and paper adds nothing to "proven". Neither tally 2's design round nor refcore's runs move a status here: refcore is a reference interpreter, not the engine. What the design changes is the second status column: it says whether Tally now has a construct for the row.

**Statuses, after the design:**
- **proven**: as before (v2's spikes). The *Tally* column says where Tally keeps it.
- **designed, untested**: Tally has a construct; no engine has run it.
- **gap, designed**: a gap the spec had already adopted a change for (rows 24, 26, 27, 29, 30, 33). Tally has a construct, and the row stays a gap until built.
- **gap, change taken**: `changes.md` proposed a change; the design takes it (`DECISIONS.md`). It stays a gap until built.
- **gap, change taken differently**: the design meets the need another way, and says how. It stays a gap until built.
- **out of scope by nature**: as before. Tally 2 has no `bound` keyword: where a case needs one of these steps, the model writes it as an ordinary hole with its reason (D-15, P-17), which prints its question, never a silent approximation (`PERFORMANCE.md` §9).

**Columns:**
- *Evidence* is the cases of `tmp/verification/bounds.md` (the checks' `bounds_rows`), unchanged. For rows 50–53 it lists the cases that need the ability, and how they were found.
- *Tally* is where 2.1 keeps the ability: L = `LANGUAGE.md`, E = `ENGINE.md`, P = `PERFORMANCE.md`, O = `OPERATIONS.md` (tally 1.0.1's, still stale: `STALE.md`).
- The models' own use of each construct is in `coverage.md`. No case model samples a random fact, so rows 13, 20, 46 and 51 rest on the design alone (`coverage.md` K13; L §5.16 cost), and LH-18's step 6 is computed exactly, so row 49's out-of-reach step is LH-17's alone.
