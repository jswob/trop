## P0 report: `engine/tools/parsecheck/` is built

The syntax checker is built. 95 of the 96 spec files parse, and the one that fails is a spec finding (S:1), not a grammar bug. The ambiguity run finds nothing in any file, and `--selftest` passes 89 of 89. I made no writes outside `engine/tools/parsecheck/`, and `engine/spec` is unchanged.

**1. What was built**
- **`tally.lark`**: one production for each EBNF production of L §2.3, each under a comment naming it. It uses Lark Earley with token-based scanning, not scannerless. Optional and repeated lines are split into small `_x` helper rules; without that, Lark expands `version` into 1536 alternatives and Earley ran about 8 minutes.
- **`parsecheck.py`**: does what the brief asked (`PATH ...`, `-v`, `--selftest`, `--ambiguity`).
  - It has its own L §2.1 lexer. Each two-space indent level becomes one `INDENT` token. It refuses tabs, odd indents, `#` comments, escapes other than `\"` and `\\`, non-ASCII outside strings, bad currency codes and `\r`. A key token keeps its `-`.
  - A contextual word such as `start` is sent as a literal and is still accepted as an id.
  - Each top-level item is parsed on its own, so the report gives the first failure of each item.
- **`README.md`**: covers what the tool checks and doesn't, that it is independent of the Rust loader (whose builder is not to read it), setup, and the grammar notes.
- **lark==1.2.2**, pinned exactly; it works on Python 3.14. A full run over the spec takes about 90 seconds. No `__pycache__` is left under `engine/`; I removed the ones pip created inside `.venv`.

**Rules done outside the grammar, or partly:**
- **Parse rule 1** is in the grammar. After the split, the value or right side has no `=` at bracket depth 0, so the split falls at the last ` = ` and anything else fails as `LOAD-PARSE` would.
- **Parse rules 2 and 3** are in the grammar.
- **Parse rule 4** is partly outside. The lone `-` takes no subscript in the grammar, and Python refuses a lone `-` followed by a token that can start an operand (`- - a`).
- **Parse rule 5** is partly outside. Python refuses `flows(…) in CUR` when no `at` follows.
- **Nesting limits** are counted in Python on the parse tree: depth 8 (`LOAD-DEPTH`) and 4 nested `as if` (`LOAD-ASIF`).
- **`"/year"`** must touch: `/` and `year` with no space between.

**Grammar narrowings to know about:**
- Where the EBNF derives one text twice only because token classes overlap (a bare id is a lit, a key and a ref; an axis pin is also a value pin; `down` and `up` are both a mode and an id), the grammar keeps one derivation.
- Built-ins that have a form of their own (`agg`, `flowsx`, `crps`, `distfn`, `prorata`) are read only by that form. `min`, `max`, `bal` and `plan_low` can still be called plainly, because §2.3 and §5.13.1 write them that way. S:2 is why.
- `rk` accepts a keyed place, as LA-1's annotation says.
- Blank lines are allowed only between items.
