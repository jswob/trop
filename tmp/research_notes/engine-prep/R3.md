# R3: parallelism without losing determinism

**Question:** how the engine uses up to 6 cores and still prints the same bytes, with equal result hashes on 1 and 6 workers (DONE gate 6). **Date:** 2026-10-30. **Agent:** R3, session 8 (engine prep, part A). Paper only.

---

## Summary

1. **Parallel map, sequential fold.**
   - Every split in Tally's work is a set of independent evaluation contexts over a shared layer: paths, axis combinations, `windows each` leaves, rolling origins, scenario timelines, joint members. Each context is a pure function of itself (E §3.2, §7; L §7.4).
   - So workers only *map* tasks into slots indexed by task number. Every merge then runs on one thread, in index order, as refcore's loop does: statistics, the choice of refusal, the hole union, the output order.
   - E §7 step 3 already keeps all N terms, so this stores nothing extra. With no reduction across threads, no grouping question can arise. (refcore `eval2.py:898–921`.)
2. **The order is no longer forced by arithmetic, but it is forced by refusals.**
   - Tally 2.1 took the digit cap off a path statistic's sums (L §7.1, R-13: "the engine's, unbounded or exact by any method"), so phase 1's SO-22 is moot for sums.
   - Which of several refusing paths prints is fixed only by refcore: the first in path order, ahead of any hole. The spec doesn't say so.
   - rayon documents the opposite for its own error paths: "If there are multiple errors, the one returned is not deterministic" (rayon 1.12.0 `FromParallelIterator`, docs.rs, fetched 2026-10-30).
3. **Keep R-42 (std `thread::scope`, no rayon), amended.**
   - The tasks are coarse and few, so rayon's work stealing buys little.
   - rayon's `reduce`, `fold`, `sum` and error collection are documented as unspecified, and its default pool size comes from `RAYON_NUM_THREADS` or the CPU count.
   - New finding: std's default thread stack reads the `RUST_MIN_STACK` environment variable unless `Builder::stack_size` is set (std 1.99.1 docs, fetched 2026-10-30). A plainly spawned worker therefore reads the environment (against R-39). It also gets 2 MiB against the main thread's 8 MiB, so a deep expression could crash on 6 workers and not on 1.
4. **SHA-256 addresses are a counter-based generator keyed by application variables.**
   - This is the design Random123 recommends because it is "machine-independent… even with different levels of physical parallelism" (Salmon et al., SC11, p. 2).
   - It gives with no state what NumPy's `SeedSequence.spawn`, JAX's split keys and R's L'Ecuyer streams build machinery for.
   - To check: the address text is injective (it is, parsing from the right; refcore hashes UTF-8, `dists.py:635`); 64-bit truncation gives about 0.03 equal pairs per 10⁹ draws, the same as true uniforms on a 2⁶⁴ grid.
5. **Memory.**
   - Workers share the frozen layer by plain borrow (`&`), with no `Arc` and no lock.
   - Peak ≈ shared layer + W × (one live path layer and its walk) + kept terms. The terms take about 3 MB at 10 000 paths × 10 terms.
   - The per-path layer at B-12 size is the unknown, and only a build can measure it.
   - The worker count is an argument, so lowering it changes no byte.
6. **A trap off the merge path.** refcore's Maritz–Jarrett standard error is exact: integers the size of N^N, and about N²/2 Horner steps. That is 40 000 digits and 5×10⁷ steps at D-10's 10 000 paths, and 500 000 digits and 5×10⁹ steps at the 100 000 cap. The engine must refine intervals to the 1e-6 rounding, which L §7.1 allows.
7. **Testing gate 6.**
   - Run W ∈ {1, 2, 3, 5, 6, 7} on the cases and on T's generated realities, with a test-only reversed-completion mode and planted violations.
   - Ban channels, locks and atomics outside the module.
   - loom 0.7.2 can't model `thread::scope`; shuttle 0.9.9 can. Neither is needed while the module shares no mutable state.

Decisions: D3-1 tool, D3-2 first-build scope, D3-3 merge rule, D3-4 freezing the shared layer, D3-5 memory, D3-6 gate 6 tests, D3-7 the Maritz–Jarrett method.

## Findings

### Q1. Where the work splits

**The shape** (inference from E §3.2). A cell is (item, keys, context). The context is trimmed to what the item can depend on, and the result is a pure function of the cell. So contexts that differ only in the split component (path, axis options, pins, cut class, sub-window, world) evaluate apart, and they share every cell whose trimmed context omits that component. The repeat counts below are from shape.md.

| Split | Independent? | Shares | Merge needs | Weight |
|---|---|---|---|---|
| **Paths** (E §7) | yes: "a pure function of its seed and number" (L §7.4); own layer over the shared one (E §7.2) | E §7 step 1's shared layer: cells no random fact reaches, law outside the random cone | N terms in path order; statistic, counts, SE, horizon; the refusal and hole choice (Q3) | LH-17-mc-light 0.2 s a path; B-12 about 5 min a path (benchmarks row 5) |
| **Axis combinations** (≤ 64, `LOAD-FORKS`) | yes: a timeline each (PERF §3) | cells that reach no axis | option order | ≤ 64 timelines |
| **`windows each`** (L §4.4) | yes per leaf; leaves nest (L l.672), so the tree is enumerated, then run | cells outside the window's cone; the walk prefix | sub-window order | A: 64 walks × 5 477 days |
| **Rolling origins** (E §8) | yes: one cut class each | law cells; shared cut classes | index order | 24 origins ≈ 1 run + 24 partial walks (PERF §3) |
| **Scenarios, pins** | yes over the base (PERF §3) | the base layer; uniforms by address | base first (E §9.3 compares them) | X: 20 walks |
| **Timelines** (E §3.3) | yes: the general form of the four rows above | trimmed cells | ask order | — |
| **Joint members** (BUILD-NOTES J) | yes: own context and memo; walk on demand | nothing between members | keyed by member | E2: 8 walks |
| **Asks** | values yes; but they fill one memo on demand | the whole memo | ask order | E2b: +4 walks |
| **Inside one walk** | no: sequential (E §4.2, strata L §5.14.2) | — | — | E1 |

**One mechanism serves all.** The big multipliers (64× A, 8–12× E2, 20× X, N paths) are all one kind of split: a task list run as a parallel map over a frozen shared layer, merged in task order. The exceptions are asks, which need a concurrent memo, and the walk itself (inference).

**Prefix sharing composes with it.** shape.md item 3 puts the order of magnitude in skipping empty days and sharing walk prefixes. A prefix is a dependency: walk once to day d, clone the state, then map the suffixes. Each live task costs one cloned walk state (inference).

**Shared cells are computed on demand** (E §3.2). A task may need a shared cell nobody has computed yet. It can then either write into a shared memo under locks (salsa's way: snapshots and locked slots; salsa 0.28.5 has rayon as an optional dependency, docs.rs fetched 2026-10-30), or compute the cell into its own layer. The value is the same either way, since a cell is pure; only the work is duplicated. D3-4 frames the choice.

### Q2. The tools

**`std::thread::scope`** (std 1.99.1, stable since 1.63.0; fetched 2026-10-30):
- "scoped threads can borrow non-`'static` data": workers read `&Shared`, no `Arc`.
- Unjoined threads "will be automatically joined", and "If any of the automatically joined threads panicked, this function will panic… join them before the end of the scope". So the module joins in block order, and the panic it reports is the lowest block's.
- **Stack** (std `thread` docs): "Currently, it is 2 MiB on all Tier-1 platforms". It can be set by `Builder::stack_size` or by "the `RUST_MIN_STACK` environment variable… setting `Builder::stack_size` will override this"; "the stack size of the main thread is not determined by Rust".
  - So `Scope::spawn` reads the environment.
  - A 1-worker run on the main thread (8 MiB on macOS) and a 6-worker run on 2 MiB stacks differ in the depth they survive. refcore runs in a 512 MB stack (`cli.py:516`). E §3.2 removes recursion for recurrences, not for expression trees.
  - The fix: `Builder::new().stack_size(S).spawn_scoped(scope, f)` with S passed in, and the 1-worker run on one spawned worker of the same module (inference).

**rayon 1.12.0** (crates.io: newest, 2026-04-14; docs.rs, fetched 2026-10-30):
- **Order kept:** order is kept for indexed `collect`, but only by example and adapter text ("relative order where that is visible in `collect`, `reduce`", `take_any`). `Vec`'s `FromParallelIterator` says only "Collects items… into a vector".
- **Order not kept:**
  - `reduce`: "the order in which `op` will be applied… is not fully specified";
  - `fold`: "The number of results is nondeterministic, as is the point where the breaks occur";
  - `sum` and `product`: not deterministic for a non-associative `+`;
  - `try_reduce`: "it is not specified which [error] will be returned";
  - `Result` collection: "the one returned is not deterministic".
- **Fixed chunks exist:** `fold_chunks` ("fixed-size chunks, performing a sequential fold() on each") and `by_uniform_blocks`. They are reproducible by construction, though no doc promises it (inference).
- **Pool size:** with `num_threads` unset, it comes from "`RAYON_NUM_THREADS`… or the number of logical CPUs". An explicit n "start[s] at most this number of threads".
- **What it would buy:** work stealing and nesting.
- **What it would cost:** a dependency tree, six method bans (A1 V-88, D-6), an explicit pool, and the "which error" rule rewritten by hand anyway.

**Others** (crates.io, fetched 2026-10-30):
- **crossbeam-utils 0.8.23:** its scoped threads are made redundant by std's. Its channels deliver in finishing order, which is exactly the bug R-42 prevents.
- **chili 0.2.1** (heartbeat `join`, last release 2025-03), the **par-iter** fork onto chili, and **forte** ("under development") (search results, fetched 2026-10-30): none documents determinism. None is recommended (inference).

**Cost to read** (inference). The `scope` module is about 40 lines: split into blocks, spawn W workers with an explicit stack, each fills its own `Vec`, join in order, concatenate. To a TypeScript reader that is `Promise.all(chunks.map(run))` then `.flat()`: order kept whatever finishes first. Rayon's `par_iter().map(f).collect()` is shorter, but its guarantee lives in rayon's internals.

**What strict projects do** (Q6):
- **ruff** runs `par_iter().fold(…).reduce(…)` over files, then `all_diagnostics.inner.sort_by(Diagnostic::ruff_start_ordering)` (`crates/ruff/src/commands/check.rs`, fetched 2026-10-30). Determinism comes from a total sort after an unordered merge. Tally's terms carry their path number, so values could be merged that way too, but the refusal choice still needs the order rule (Q3).
- **TigerBeetle** "uses a single core by design" (docs.tigerbeetle.com/concepts/performance).
- **FoundationDB** simulates "an entire FoundationDB cluster within a single-threaded process… Determinism is crucial" (apple.github.io/foundationdb/testing.html).
- The strictest projects keep the deterministic core single-threaded. Tally's version of that: one context is evaluated on one thread, and parallelism lives only in the task module above it.
- Cargo's and typst's orders weren't researched; no decision turns on them.

**Verdict on R-42: keep it, with these amendments** (D3-1):
- (a) spawn only via `Builder::spawn_scoped` with a stack size passed in;
- (b) the 1-worker run goes through the module;
- (c) "path order" becomes "task-index order";
- (d) ban `std::sync::mpsc`, `Mutex`, `RwLock`, `Condvar` and `std::sync::atomic` in the library outside the module;
- (e) `Scope::spawn` is banned.

### Q3. Deterministic merges

**Sums are order-free in 2.1.** L §7.1 (R-13): "The cap applies to a value at a key. A path statistic's own accumulation… is the engine's, unbounded or exact by any method, and must give the printed rounding exactly". §5.16 adds "the 4 096-digit cap doesn't reach them". Only the mean itself is capped, and it doesn't depend on order. Fixed chunk or tree shapes are a speed choice, not a correctness one.

**refcore departs from this in one branch.** `mean` over terms in convertible units, or over rates, sums with `arith('+')` (`eval2.py:952–958`, "each partial sum a value, as on 2.0"). `arith` checks digits (`evaluate.py:4340`), so each partial sum is capped in path order. The single-unit branch sums uncapped, as the spec says. The engine follows the spec, and a gate 10 disagreement there is refcore's. It is rare: it needs a partial sum past 4 096 digits.

**Refusals and holes: the order matters.** refcore's loop runs paths 1..N. A refusal leaves the loop at once; holes are merged after it. The precedence the engine must copy:
1. the **first path in path order** whose `where` is `none` (`RUN-NONE`, "a where is none here") or whose term refuses: that refusal, with its message;
2. else one hole, the union of every path's questions (order-free, L §8.1);
3. else `RUN-EMPTY`;
4. else `RUN-NONE` for a kept `none` (its message names no path);
5. else the statistic.

Messages differ by path (`RUN-KEY`'s "draw <n> of <x> passes the last slot"), so which path refuses decides the bytes. refcore evaluates each query of a line over all paths before the next, so the rule is **term in line order, then path order** (inference from `eval2.py:885–921`). An engine that evaluates every term on a path before the next path must keep outcomes per term and apply the rule after.

**Early cancellation** is output-safe if bounded by index: skip only paths above the lowest refusing path known so far. It needs an atomic, though. Leave it out of the first build; refusals are not the hot path.

**Statistics** (L §5.16; no floats, N-219):
- `share`: n of M is exact. Its standard error is a correctly rounded square root, which defines the printed value whatever the method, so SO-23 is settled.
- `mean`: Σx/M and s² are exact; s/√M is correctly rounded. Order-free.
- `quantile`: sorting makes the order matter. Equal numbers can carry different `≈` enclosures (`enc`), and refcore's stable sort on path-ordered input picks the lowest path among them. So the engine sorts stably by (value, path), on input in path order; R-43 already bans unstable sorts. Samples that are keys sort by index order.
- **Maritz–Jarrett** (`eval2.py:1014–1061`): S(i) = N^N·I(i/N) in exact integers by Horner's rule:

```
$ python3 -I -c 'import math; [print(N, round(N*math.log10(N)), N*(N//2)) for N in (1000,3000,10000,100000)]'
1000 3000 500000
3000 10431 4500000
10000 40000 50000000
100000 500000 5000000000
```

  (N, digits of N^N, Horner steps at the median.) At N = 10 000 this is likely seconds to minutes per quantile, and at 100 000 out of reach (inference: no per-step figure was measured). The fix is interval evaluation of the incomplete Beta, refined to the 1e-6 cell. Its terms W_i·x(i)^k are independent, so they can be split across workers, order-free (D3-7).
- The **horizon** (a maximum) and the **register** (a set printed sorted) are order-free.

**Chunking** affects cost, not values. E §7 step 5 says "contiguous blocks, one per worker". Dynamic fixed-size chunks (one atomic counter, results into slot k) print the same and balance uneven paths. The spec's wording names a means; its guarantee is the merge (§7).

### Q4. Per-path draws

**Tally's scheme** (L §5.16): A = `address|S|p` → k = the first 8 bytes of SHA-256(A), big-endian → u = (k + ½)/2⁶⁴ → `quantile(D, u)`. refcore hashes UTF-8 (`dists.py:635`).

**Prior art** (fetched 2026-10-30):
- **Random123** (Salmon, Moraes, Dror, Shaw, SC11): x_n = b_k(n). "Applications can choose to derive k and n on the fly from… application variables (e.g., particle identifier…)… machine-independent streams… (even with different levels of physical parallelism…). This approach permits deterministic results across different computing platforms" (p. 2). Its families, AES and Threefish included, pass BigCrush. Tally's address is that application variable.
- **JAX:** explicit keys, `split` and `fold_in`, Threefry. Threefry and Philox give results identical across devices and shardings, and `jax_threefry_partitionable` has been the default "as of JAX v.0.5.0", for efficient sharded generation. The lesson (inference): a scheme tied to the work's layout had to be reworked to stay layout-independent.
- **NumPy 2.5** `SeedSequence.spawn`: streams "independent (with very high probability)", collisions about n²·2⁻¹²⁸. It warns that seed plus worker id makes "overlapping sets of worker seeds". Tally's `|` separators avoid that: seed 7 path 12 and seed 71 path 2 are different texts.
- **R** `clusterSetRNGStream` "distributes streams to the members of a cluster": streams belong to workers, so results follow the cluster size unless each task takes its own stream (inference).

**What the address scheme gives** (inference):
- no state and no stream, so neither workers, chunks nor schedule can touch a sample;
- `path p` is recomputable alone;
- common random numbers across scenarios and pins (E §7);
- adding a random fact shifts no other fact's draws (a stream generator shifts every later one);
- nothing shared between workers.

**What to check:**
1. **Injectivity.** S and p are decimals with no `|`, so A parses from the right. A is injective if the canonical print of (fact, keys) is (L §2.4). Test two addresses that differ inside a text key.
2. **Encoding.** UTF-8; the spec doesn't name it (§7).
3. **Truncation.** 10⁹ draws give n²/2⁶⁵ ≈ 0.027 expected equal pairs, the same as true uniforms on a 2⁶⁴ grid. The smallest u is 2⁻⁶⁵ (a normal tail near −9.3σ).
4. **Speed.** sha2 0.11.1 (2026-10-12) picks `aarch64-sha2`, `x86-sha` or `soft` at run time (docs.rs/sha2). The digest is the same either way, so the choice changes no byte. An address under 56 bytes is one compression block. The correctly rounded quantile likely dominates L §5.16's 0.3–1 µs (inference).
5. **Golden vectors.** NIST vectors (BUILDER §7), plus golden (A, k, u) triples from refcore.
6. **One hash per address per path.** A sample is a path-layer cell.

### Q5. Memory per worker

**Sharing** (std `Arc` docs, fetched 2026-10-30):
- `Arc` uses atomic counts that "are more expensive than ordinary memory accesses", and is `Sync` only if T is.
- Under `thread::scope`, workers borrow `&Shared` with no count and no lock. An `Rc` or `RefCell` inside the layer is then a compile error, not a race.
- Store small numbers inline (> 99.9 % fit 64 bits, shape.md). Put only big-tier values behind a pointer. Six workers cloning one hot `Arc` make cache-line ping-pong (inference).

**Peak** (inference, from E §7 and PERF §5):

```
peak ≈ shared layer + W × (one live path/task layer + its walk state) + kept terms + output
```

- **Terms:** 10 000 × 10 × 32 B ≈ 3.2 MB. Money is whole cents, so values fit inline even though rationals vary in size (SO-24).
- **Shared layer:** refcore's largest memo was 2.27 M cells in 4.95 GB (X). At an assumed 100–300 B a cell in Rust, that is about 0.2–0.7 GB (inference; unmeasured). Paths keep no read sets (PERF §5: "a flat table, dropped after the path").
- **Per path:** unknown. One B-12 path passed 18 GB in refcore (benchmarks row 5), and its cone holds a walk to 2028 with law per path.
- **Cap:** with the shared layer under 1 GB and 1 GB of headroom, each of 6 workers has about 1 GB for its live layer (inference).

**Safety without guessing:**
- W is an argument, so fewer workers print the same bytes;
- a per-path bump arena (bumpalo 3.20.3, 2026-05-22), freed whole after each path, avoids fragmentation across threads. It is an option, not a pick;
- prefix sharing costs one cloned walk state per *live* task.

### Q7. Testing gate 6

DONE gate 6 asks for "equal result hashes with 1 and 6 workers, and across runs"; E §9 says "every case is run twice, with 1 and with 6 workers".

**By machine:**
1. **The sweep.** W ∈ {1, 2, 3, 5, 6, 7} on every case and on T's generated realities (gate 10's generator), driven by proptest 1.12.0 (2026-10-10; A1 V-124). 5 and 7 make uneven blocks, and 7 oversubscribes the 6 cores.
2. **Reversed completion.** A test-only switch runs the blocks sequentially in reverse or in seeded shuffled order and merges as usual. A merge by finishing order fails it every time, without relying on the OS scheduler (inference).
3. **Planted violations** (phase 1's pattern): each must turn a test or a lint red:
   - a merge in finishing order;
   - `Scope::spawn` without a stack size;
   - a `HashMap` in a path layer;
   - the refusal taken from the highest path.
4. **Lints.** clippy `disallowed-methods` and `-types` (ESLint's `no-restricted-imports`, roughly) on:
   - channels, locks, `Condvar` and atomics in the library;
   - all thread starters, `Scope::spawn` included;
   - `available_parallelism`;
   - one counted `#[expect]` in the module (R-42, R-108).
5. **Across runs and machines.** The pair runs twice. K-25: Linux per PR, macOS and i686 nightly.
6. **Stack.** The deepest-expression case runs at W = 1 and W = 6 on the same explicit stack.

**Schedule explorers.**
- loom 0.7.2 (last release 2024-04-23): its `thread` module has no `scope` (docs.rs, fetched 2026-10-30).
- shuttle 0.9.9 (2026-10-29) has `thread::scope`. It is "not sound (a passing Shuttle test does not prove the code is correct)", and every `std::sync` primitive must be swapped for its own.
- While each worker owns its `Vec` and results travel only through `join`, there is no interleaving to explore. Shuttle earns its place only if an atomic enters the module, through dynamic chunks or cancellation (inference).

**By review only:**
- no task reads state outside its context and the frozen layer;
- the Q3 rule is the one coded;
- the layer is handed out as `&`, with no interior mutability, which is what lets the compiler enforce the freeze.

## What this means for Tally's engine

- **The work repeats, and the copies are independent.** The engine redoes a lot of work: 64 copies of one walk in household A, 20 in X, up to 100 000 Monte Carlo paths. Each copy is like a pure function in TypeScript, so the copies can run on 6 cores at once. A **thread** is like a Node `worker_threads` worker that shares memory.
- **Workers fill numbered slots; one thread reads them in order.** That is `await Promise.all(chunks.map(run))`, then a plain loop. Slot 7 is always path 7, whoever finishes first. Totals, standard errors, which error to print and the output order are all decided in that loop, the way the reference interpreter decides them. So 1 and 6 workers print the same bytes.

**Terms:**
- **`std::thread::scope`:** Rust's built-in "start threads, wait for all of them before leaving this block". The threads may read the caller's data without copying it.
- **rayon:** a popular crate (an npm package) that spreads work over a thread pool automatically. Several of its combining operations are documented as unordered.
- **`Arc`:** a thread-safe refcounted pointer.
- **`&`:** a read-only borrow, proven safe by the compiler.
- **`Sync`:** the compiler's mark for "safe to read from many threads".
- **`Mutex`, atomics, channels:** ways for threads to talk mid-work. They are banned outside one module, so results return only the orderly way.
- **loom and shuttle:** tools that try many thread schedules.

**Changes from phase 1:**
- R-42 stays, with five small amendments. The key one is an explicit thread stack size; otherwise Rust reads it from an environment variable.
- The merge order is still needed, now for "which path's refusal prints" rather than for arithmetic.
- The module serves every independent split: paths first, then timelines.

**Unchanged:**
- One context runs on one thread: the walk, the strata, one path's memo. TigerBeetle and FoundationDB keep their cores single-threaded too.
- The bigger speed-ups shape.md found are R1's and R2's ground: skipping empty days, sharing walk prefixes, the memo key. Parallelism multiplies them by at most 6.

## Decisions for the user

**D3-1. The threading tool.**
- *Problem:* run independent work on 6 cores without the finishing order reaching the output.
- *Options:*
  - (a) R-42 as written;
  - (b) R-42 amended: `Builder::spawn_scoped` with a stack size passed in; the 1-worker run through the module; task-index order; channels, locks and atomics banned outside the module; `Scope::spawn` banned;
  - (c) rayon with a local pool, indexed `collect` only, and `reduce`, `fold`, `sum`, `product`, `try_*` and the global pool banned;
  - (d) chili or forte.
- **Pick (b).**
- *Cost:*
  - (b): one lint list and about 40 readable lines, no dependency, equal speed for coarse tasks, low risk.
  - (c): about 20 fewer lines plus stealing and nesting, for a dependency tree, six bans, and an order guarantee that lives in rayon's docs.
  - (d): unproven.

**D3-2. What runs in parallel in the first build.**
- *Problem:* every split could run in parallel. Asks need a concurrent memo; the rest need a task list.
- *Options:*
  - (a) paths only (E §7; gate 12's "≤ 1 s on 6 workers");
  - (b) paths plus timelines (axis combinations, `windows each` leaves, rolling origins, scenario timelines), all through one module over a frozen layer;
  - (c) (b) plus members and parallel asks.
- **Pick (b).** Members and asks come later, through the same module (seam J already makes members contexts).
- *Cost:*
  - (b): a task-list builder per split kind. It reaches A's 64× and X's 20× at up to 6× speed, with one mechanism to read.
  - (c): a concurrent memo, the hardest code to audit.

**D3-3. The merge rule.**
- *Problem:* the spec doesn't say which refusal or hole prints when several paths or terms produce them, and gate 10 wants refcore's bytes.
- *Options:*
  - (a) refcore's rule: per line, terms in line order; within a term, the first refusing path (a `none` `where` counts), else the union of holes, else `RUN-EMPTY`, else `RUN-NONE`. Kept values arrive in path order, and the quantile sorts stably by (value, path);
  - (b) any other rule, such as the most severe code, which breaks gate 10.
- **Pick (a)**, logged as a spec observation, with no early cancellation in the first build.
- *Cost:* one scan; reads as plain rules. Risk: a later spec may choose otherwise.

**D3-4. Freezing the shared layer.**
- *Problem:* shared cells are computed on demand. The options are locks, or duplicated work.
- *Options:*
  - (a) an eager pre-pass of the static non-random cone;
  - (b) warm up: run task 1 alone, freeze, map the rest; misses go into each task's own layer and are folded back after the map, in task order (the values are identical);
  - (c) a concurrent memo, salsa-style.
- **Pick (b)**, with a counter of shared cells computed locally. Move to (a) or (c) only if that counter shows heavy duplication.
- *Cost:*
  - (b): no locks; the duplication is unmeasured (G1).
  - (a): may compute cells nobody reads.
  - (c): locks in the hot path, the hardest to test.

**D3-5. Memory per worker.**
- *Problem:* the shared layer plus 6 live path layers must fit 8 GB at D-10, B-12 and household-bands, and the size of a path layer is unknown.
- *Options:*
  - (a) always 6 workers;
  - (b) W passed in, the CLI defaulting to 6, and a flag to lower it (output unchanged);
  - (c) the CLI reads free memory and picks W.
- **Pick (b).** Weigh a per-path arena once layer sizes are measured.
- *Cost:* (b) costs nothing. (c) reads the machine, against R-42's "never from the machine".

**D3-6. Gate 6 tests.**
- *Problem:* 1 vs 6 on the cases catches a finishing-order merge only if the scheduler happens to reorder.
- *Options:*
  - (a) 1 vs 6 as written;
  - (b) the W sweep on the cases and generated realities, reversed or shuffled completion, planted violations, the lint bans, and the deep-stack case;
  - (c) (b) plus shuttle now.
- **Pick (b).** Add shuttle if an atomic enters the module.
- *Cost:* (b) about 6× the case runs in CI, which are fast, plus one test switch. (c) swaps primitives that aren't used.

**D3-7. Maritz–Jarrett at size.**
- *Problem:* refcore's exact method takes about N²/2 steps on integers of N·log₁₀N digits, beyond reach at 100 000 paths and slow at D-10's 10 000.
- *Options:*
  - (a) copy it;
  - (b) refined interval evaluation of the incomplete Beta to the 1e-6 rounding (L §7.1 R-13's "any method"), checked against the exact method at small N;
  - (c) cap N, a language change, so no.
- **Pick (b)**, with its terms split across workers.
- *Cost:* (b) is a careful numeric kernel and goes on gate 8's mutation list. (a) likely fails gate 12 at size (inference).

## Contradictions with phase 1 or the spec; spec observations

**Phase 1:**
- **SO-22** ("the path-order merge is required… because `RUN-DIGITS` is checked on partial sums") is superseded by L §7.1 R-13 (2.1). The order is still required, now for D3-3's refusal choice.
- **SO-23** is settled: L §5.16 rounds each standard error correctly to 1e-6.
- **R-42 and BUILDER §7** name `thread::scope` but not the stack. `Scope::spawn` reads `RUST_MIN_STACK`, an environment read R-39 means to forbid, and differs from the main thread's stack. This is a hole in the rule, not a contradiction; D3-1 (a) and (b) close it.
- **A1 D-5 and A4 D10** ban thread starters but not channels, locks and atomics, the other routes by which finishing order leaks. D3-1 (b) adds them.

**refcore against the spec** (refcore is frozen; for the lead): `eval2.py:952–958` caps the partial sums of a mixed-unit or rate `mean` in path order (`evaluate.py:4340`), while L §7.1 R-13 leaves accumulations uncapped. The engine follows the spec.

**Spec observations** (never fixed):
- **SO-paths-1:** which refusal prints when several paths or terms refuse is not stated. L §8.4 says a refusal "outranks" a hole; L §7.5's "combined in path order" speaks of sums. refcore takes term order, then the lowest path. This is the paths' counterpart of SO-4.
- **SO-paths-2:** L §5.16 doesn't name the byte encoding of A. refcore uses UTF-8, consistent with L §2's files.
- **SO-paths-3:** E §7 step 5's "contiguous blocks, one per worker" is a means. Its guarantee is the merge. Dynamic fixed chunks keep the meaning but not the wording.
- **SO-paths-4:** which of several equal quantile values with different `≈` enclosures prints is fixed only by refcore's stable sort.
