### Q2. A simple Rust subset for LLM-written code

ast-grep (pinned at 0.51.0 in the scaffold's CI, still the latest today [S12]) matches tree-sitter-rust node kinds. `dynamic_type`, `type_parameters`, `trait_item`, `lifetime`, `closure_expression` and `macro_definition` all exist [S11].

| Limit | Saves the reader | Enforced by | Speed cost |
|---|---|---|---|
| **No `dyn Trait`**; a closed set is an `enum` plus exhaustive `match` (R-62) | every case listed in one place | ast-grep `dynamic_type`, error with a counted exception | **a gain**: dynamic dispatch "prevents the compiler from choosing to inline" [S13]. enum_dispatch 0.3.13 reports up to 10× over `dyn` on its stated benchmark (1 024 objects, `black_box`) [S14] |
| **No own type parameters** (`fn f<T>`, `impl<T>`); std containers are fine | one concrete type per name | ast-grep `type_parameters`, report and review | none at run time (monomorphised, "static dispatch" [S13]); faster compiles [S3] |
| **No `impl Trait` arguments** | one signature form | clippy `impl_trait_in_params` (restriction) [S20] | none |
| **No new trait without two implementations** (BUILDER §11) | no abstraction ahead of need | ast-grep `trait_item` report, review | none |
| **Explicit lifetimes only on short-lived views** (the cursor, a borrowed slice); long-lived links are ids into tables (BUILDER §3) | the hardest Rust idea stays in a few files | ast-grep report on structs with a `lifetime`; the pedantic lifetime lints | a table lookup per id; clones cost more and are counted by R-74 (inference) |
| **No `macro_rules!` in the library** outside the lead's list; no own proc macros | no hand-expanding; clippy and cargo-mutants see the code (R-13, R-73) | ast-grep `macro_definition` (R-73's rule) | none |
| **Chains of at most about 4 steps; one-expression closures, none nested** | a `for` reads line by line | review; ast-grep report on nested `closure_expression` | none: loop 19.62 ms, iterator 19.23 ms [S16] |

**Why this pays (inference):**
- Every set of cases (node kinds, value kinds, codes, distributions) is fixed by the frozen spec. So `enum` plus `match` is both the fastest and the most readable shape.
- Generics, traits and `dyn` serve unknown future callers, and the engine has none.
- **Cost:** a little duplication, which rust-analyzer and TigerBeetle accept.

### Q3. Enforceable size and complexity limits

**What the lints measure** (clippy master source and book, today):
- **`too_many_lines`** (pedantic, default 100): counts lines with code only, and skips closures [S17][S15]. The scaffold allows it in the strict passes (R-67) and reports it at **60** in `tools/advisory.py`. A5 SC-6 said 100.
- **`cognitive_complexity`** (restriction, default 25): 1, plus 1 per `if`, **plus 1 per multi-arm `match`, whatever its arm count**, plus 1 per guard, minus returns. Clippy's own docs: "The true Cognitive Complexity of a method is not something we can calculate using modern technology" [S18].
- **`excessive_nesting`** (complexity, default 0 = off) [S19]:
  - A syntax-level pass. Every `{}` block, `impl` and inline `mod` adds a level, so a method body starts at 2.
  - It skips macros.
  - The scaffold denies the whole `complexity` group (`engine/Cargo.toml`), so **a threshold in `clippy.toml` makes it an error at once**. The advisory pass uses 4.
- **`too_many_arguments`** (complexity, 7) and **`type_complexity`** (complexity, 250) [S20][S21]: **already errors** in the scaffold.
- **File size:** clippy has no limit [S15]. rustc's tidy caps files at 3 000 lines and lines at 100 columns [S22].

**Evidence on length conflicts:**
- 785 000 Java methods: "keep their Java methods under 24 lines" [S23].
- A re-analysis calls the optimum "a sloppy analysis in one paper" [S24].
- Ousterhout warns against "teeny-tiny methods" and "arbitrary numerical limits" [S25].
- GitClear, via a secondary report, measured an eightfold rise in duplicated blocks in 2024 [S26]: the LLM-era risk is duplication, not length.

**Should K-21 change? Partly** (inference):
- Phase 1's reason, long dispatch `match`es, concerns length, which stays a report. Nesting is what a reader trips on.
- TIGER_STYLE's "centralize control flow" (branches stay in the parent, straight-line work goes to named helpers) meets a nesting cap without mechanical splitting.
- **Proposal:**
  - `excessive_nesting` as an **error at 5**: `impl` → body → loop → arm → `if` passes, and one level deeper fails (A1's figure).
  - `cognitive_complexity` reported at 25.
  - `too_many_lines` reported at 100.
  - Each arm of a dispatch `match` is a call or one expression (review; an ast-grep report flags arms over about 5 lines).
  - Files over 1 000 code lines are reported.
